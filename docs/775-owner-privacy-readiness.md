# #775 보호 모드의 격리 검증

0030은 기존 데이터베이스의 정책을 `legacy`로 기록합니다. API와 작업자는 같은 정책 및 세대에서만 기동하며, 팩토리 호출은 정책을 바꾸지 않습니다. 보호 모드를 켜는 운영 설정이나 명령은 이 변경에 포함되지 않습니다.

격리 시험에서 별도의 API와 analyst가 같은 합성 DB에 접속합니다. 정책을 격리한 뒤에는 기존 인스턴스의 요청과 분석 저장을 거부합니다. 보호 세대에서 생성한 신규 분석은 같은 모드의 analyst만 claim하며, 호환되는 작업자가 처리한 결과를 확인합니다. 다시 격리하면 이미 실행 중인 인스턴스와 SSE가 권한을 잃습니다. 보호 모드로 재개할 때도 새 세대로 시작합니다.

- 보호 모드의 계좌 조회나 계좌 참조 분석에는 현재 명시 소유 세대에 대해 별도로 승인한 서버 브로커가 필요합니다. 보유 계좌를 추정하는 브로커 구성은 허용하지 않습니다. 기존 계좌나 브로커 토큰을 재사용할 근거로 소유권 변경을 사용하지 않습니다.
- 텔레그램의 기존 목적지나 설정값은 소급 승인하지 않습니다. 서버에서 별도로 승인한 목적지만 현재 세대에 사용합니다. 보호 모드에서 기존 채널 설정 변경은 차단하고 공개 웹 푸시는 유지합니다.
- 구 분석의 공유값과 자료는 보존합니다. 보호 모드는 새 제출·실행 증명과 명시 공유 판정을 모두 가진 자료로만 공개 상세, 재사용, 집계와 파생 캐시를 구성합니다. 이전에 제출자 및 비계좌 여부가 확인된 본인 분석은 고정 상태만 표시합니다. 이전 계좌 보고서, 체결, 보유 알림과 채팅은 추가 귀속 근거가 필요합니다.
- 보호 분석의 TradingAgents 메모리와 작업용 파일은 실행마다 새 임시 경로를 사용하고 종료 시 지웁니다. 보호 경로에서는 체크포인트를 쓰거나 복원하지 않으며 파일 리포트와 공유 메모리에 분석 결과를 저장하지 않습니다.
- 새 펜스를 모르는 배포본은 스스로 격리할 수 없습니다. 전환 전 모든 구 API·analyst·collector와 진행 중 작업을 정리하고 접근 경계에서 격리한 뒤, 호환 세대끼리 재기동해야 합니다. 이미 전달한 외부 호출이나 알림은 회수할 수 없습니다.
- 보호 사용 이력이 생긴 DB는 레거시로 되돌리지 않습니다. 안전한 복구 상태는 격리입니다. 0030 다운그레이드는 정책을 한 번도 전환하지 않은 초기 DB에서만 허용합니다.

운영 전제에는 실제 원천 계좌·목적지와 명시 소유 세대 대조, 역할별 통합 구성 검토, 데이터 접근을 열기 전 격리와 되돌림 확인이 포함됩니다.

## legacy 에서 닫은 것

운영은 legacy 모드로 돕니다. legacy에서 다음 계좌 출구를 소유자 범위로 제한합니다.

- 계좌를 읽은 분석(`options.use_portfolio` 가 참)은 소유자(가장 작은 id)만 목록 · 총계 · 상세 · 이벤트 · SSE · 해설 · `/api/levels?run=` · `/api/playbooks?run=` 에서 읽고 지웁니다. 다른 계정에는 없는 분석과 같은 404 를 줍니다. 다른 계정의 채팅 `recent_runs` 도구와 모의 계좌도 이 분석을 빼고 계산합니다. 판정은 저장된 옵션이라 규칙 전에 다른 계정이 만든 계좌 분석도 소유자 것입니다.
- TradingAgents 메모리를 셋으로 나눴습니다. 기존 메모리 파일(소유자의 계좌 분석 결정이 쌓여 있음)은 소유자의 계좌 분석만 씁니다. 소유자의 비계좌 분석은 옆의 공개 메모리(`trading_memory.public.md`)를 새로 시작합니다. 소유자가 아닌 계정의 분석과 제출자 기록이 없는 분석은 보호 분석처럼 실행마다 새 임시 경로를 쓰고, 공유 메모리 · 체크포인트를 읽거나 쓰지 않으며 파일 리포트를 남기지 않습니다. 계좌 분석의 결정은 모든 계정이 읽는 분석의 프롬프트에 들어가지 않습니다. 기존 파일을 옮기는 운영 단계는 없습니다.
- 계좌 출구는 `tests/test_account_egress.py` 의 표 하나로 시험합니다. 두 번째 계정이 모든 출구에서 카나리아 계좌 값을 받지 않는지와, 같은 시드에서 소유자는 그 값을 실제로 받는지를 legacy · 보호 모드 모두 확인합니다.

## 남은 것

- 보호 모드 활성화(운영 전환)는 별도 이슈로 남습니다.
- 이 변경 전에 끝난 소유자의 비계좌 분석 글에는 공유 메모리를 거친 계좌 결정의 인용이 이미 섞였을 수 있습니다. 보존기간(90일)이 지나면 사라집니다.
- 대기열 순번(`queue.ahead`)은 숨긴 계좌 분석도 셉니다. 종목 · 수량은 나가지 않습니다.
- legacy 의 `/api/stats/plans` 와 보정 표는 계좌 분석을 포함한 집계(건수 · 비율)를 씁니다. 종목 · 보유 수량 · 평단은 내보내지 않습니다.

## 보호 자원 승인 기반 (#871)

보호 모드에서 쓸 Toss 원천의 승인 증거는 명시 소유자 세대와 고정 계좌·클라이언트 설정에 연결한다. 한 소유자 세대에서 원천을 바꾸면 구 분석이나 대기 중인 분석이 새 계좌와 섞일 수 있어 재승인을 거부한다. 같은 원천을 다시 쓰려면 현재 격리 세대에서 승인하고, 다음 보호 세대에서만 그 승인을 사용한다. 원천이나 자격이 바뀌는 경우에는 별도의 소유 세대 교체 절차가 필요하다.

보호 세대의 Toss 토큰 봉인 재료에는 정책 세대도 포함한다. 계좌 접근에는 해당 보호 세대에서 발급한 토큰만 허용한다. 승인 지문과 토큰 봉인 재료는 Toss 자격에서 서로 다른 용도로 파생한다. 긴급 `protected → isolated` 복귀는 기존 정책 세대 검사만 거친다.

기본 배포 팩토리는 DB의 정책 상태와 세대를 읽어 기동한다. `isolated`이면 기동을 거절한다. `protected`이면 직전 격리에서 승인된 고정 Toss 원천과 현재 바인딩을 검증한 뒤 기존 공용 브로커를 계좌 자원으로 연결한다. 토큰 저장은 기존 Toss 슬롯과 역할별 발급자 잠금을 사용한다. 검증된 보호 세대의 봉인 재료를 사용하고, 발급 시 현재 정책을 다시 확인한다. 기존 텔레그램 목적지는 보호 자원으로 승인되지 않는다.

## 운영 경고

운영 전환은 사용자 승인과 [배포 문서의 점검 절차](deploy.md#15-계좌-데이터-보호-모드-871)를 거칩니다. 격리 시 실행 중인 API·analyst·collector는 정책 확인에서 503을 반환하고 새 프로세스는 기동을 거절합니다. 안전한 복귀 상태는 `isolated`입니다. legacy의 계좌 소유자는 가장 작은 계정 ID로 판정하므로 첫 계정을 보존합니다.
