# 오늘 강할 · 약할 섹터 (#620)

국장 · 미장 따로, 오늘 시장(벤치마크 ETF)보다 **강할 확률**이 높은 섹터 3개와 낮은 섹터 3개를 고르고, 마감 뒤 채점한다.
코드: `backend/desk/day_sectors.py`. API: `GET /api/day-call/sectors?market=kr|us`(세션 필요, 대시보드 카드는 `/api/day-call/board?sectors=` 로 같이 받는다 — day-call.md). 아침 시황(#571)에 국장 한 줄.

## 섹터 표

- 국장: 벤치마크 KODEX 200(069500). 섹터 13개 — 반도체 · 2차전지 · 바이오 · 자동차 · 은행 · 증권 · 철강 · 에너지화학 · 건설 · 조선 · 중공업 · 방산 · 인터넷 · 소프트웨어(대표 ETF, `KR.sectors`).
- 미장: 벤치마크 SPY. 섹터 15개 — SOXX · XLK · XLC · XLY · XLP · XLE · XLF · XLV · XBI · XLI · XLB · XLU · XLRE · LIT · ITA.
- 국장 ↔ 미장 연결: 미 반도체(SOXX) ↔ KODEX 반도체, XLF ↔ 은행 · 증권, LIT ↔ 2차전지 등(`Sector.link`).
- ETF 와 이력은 2026-11-18 야후에서 확인했다. 대부분 2016-12 부터 있고, 2차전지 2018-09 · 인터넷 2020-10 · 방산 2023-01 부터 있다.

## 판정

- 섹터의 하루 = **초과수익**(그 ETF 종가 대비 수익률 - 벤치마크 수익률, %). 종가는 분배 · 분할을 반영한 **수정 종가**다(분배락 하락을 약세로 읽지 않는다).
- 특징(모두 판정 시각 전에 끝난 일봉)
  - 자기 섹터: 직전 세션 · 최근 5 · 20세션 초과수익
  - 연결된 상대 시장 섹터: 직전 세션 · 5세션 초과수익
    - 국장 D 일: 미장 D-1 세션(KST D 일 06:00 마감)까지
    - 미장 D 일: 국장 D 일 세션(ET 01:30 마감)까지
- 모델: 시장마다 섹터를 한데 모은 로지스틱 회귀(표준화 · 작은 ridge). 상위 3 · 하위 3 을 고른다.
  근거 문장은 확률을 가장 많이 움직인 특징을 숫자와 함께 적는다(LLM 없음). 숫자 부호와 반대로 민 특징은 "되돌림 쪽" 이라고 적는다.
- 저장하지 않는다. 입력이 모두 끝난 일봉이라 지난날 판정을 똑같이 다시 계산할 수 있다.
- 오늘 판정은 끝난 세션 전부로 학습한 모델로 낸다.
- 지난 적중률(`record`)은 지난 90세션을 그 앞 세션만으로 학습한 모델로 고른 결과다.
- 채점은 마감 30분 뒤(국장 16:00 KST, 수능일 17:00 · 미장 16:30 ET) 그날 초과수익으로 한다.
  - 상위 3 적중 = 시장을 이긴 비율, 하위 3 적중 = 시장에 진 비율, 순위 상관 = 확률과 초과수익의 Spearman.
  - 기준선은 "전날 강한 섹터 따라가기"(직전 세션 초과수익 순)다.
- 업종별 외인 · 기관 수급(한투에 업종 단위가 없다), 뉴스 테마 톤, 실적 일정은 모델에 넣지 않았다. 학습 · 검증할 과거 기록이 없어서다.
- 받는 곳: 미리 데우기(30분 캐시)가 두 시장을 데운다. 첫 요청은 20초까지 기다린 뒤 `loading` 으로 답한다.
- 다음 세션 판정에 필요한 세션(직전 세션 · 연결 시장)이 아직 없거나 진행 중이면(야후 일봉은 장중에 움직인다) 직전 세션의 판정과 채점을 보인다(`date` 는 그 세션, `target` 은 기다리는 세션). 그것도 없으면 `ready: false`. 기다리는 동안의 답은 2분만 캐시한다.
  - 국장은 KST 자정에 다음 날로 넘어가지만 미장 D-1 세션은 06:00 KST 에 끝난다. 미장은 ET 자정에 넘어가지만 국장 D 일은 15:30 KST 에 끝난다.
- 아침 시황은 판정 날짜가 시황 날짜와 같을 때만 섹터 줄을 넣는다(휴장일에 수동으로 만든 시황엔 넣지 않는다).
- 아침 시황(07:00)에는 국장만 넣는다. 미장 판정은 국장 마감 뒤에 나온다.

## 미리 계산 프로파일 (#864)

`backend`에서 저장소의 Python 환경으로 실행한다. 실제 섹터 캐시와 모델을 사용하며, ETF 30종에 종목당 2,400개 일봉과
원천 응답당 200ms 대기만 합성한다. 초기 패스, 4분 뒤, 한국장 채점 시각 직후를 같은 가상 시계로 재현한다.

```sh
python -m tests.sector_prewarm_profile --runs 3
```

비교할 때는 세 환경에서 BLAS 스레드를 1개로 맞춘다(`OPENBLAS_NUM_THREADS`, `OMP_NUM_THREADS`, `MKL_NUM_THREADS`).
#867 전후를 재현하려면 `55d8bf7^`와 `6d2d2ed` 별도 체크아웃의 `backend/tests/sector_prewarm_profile.py`에 이
스크립트를 복사하고 같은 환경에서 실행한다. 출력은 패스별 중앙값과 개별 표본의 벽시계 시간, 뷰와 봉 캐시 적중,
원천 호출 수와 최대 동시 호출 수, 계산 단계별 포함·자체 시간을 담는다. 주입 대기 합계는 설정한 지연을 호출 수만큼 더한다.
원천 활성 시간은 겹친 시간을 한 번만 센다. 포함 시간에는 하위 단계가 들어 있으므로 단계별 포함 시간을 합치지 않는다.

아래는 Windows에서 위 조건으로 버전별 `--runs 1`을 실행한 값이다. 각 칸은 벽시계 시간과 원천 호출 수를 나타낸다.

|------|-----------:|----------------:|---------------:|
| 초기 | 12.876초 · 전체 60회 | 1.776초 · 전체 30회 | 1.429초 · 전체 30회 |
| 4분 뒤 | 6.341초 · 전체 30회 | 0.127ms · 0회 | 0.161ms · 0회 |
| 세션 경계 재빌드 | 12.636초 · 전체 60회 | 1.707초 · 최근 30회 | 1.402초 · 최근 30회 |

#867 이전, 두 뷰가 모두 만료되면 같은 30종의 전체 이력을 시장마다 한 번씩 순차 조회했다. 재빌드에서 12.636초 중
12.022초가 원천 활성 시간이었고 모델 뷰 계산은 0.613초였다. 4분 뒤에는 120초 수명의 대기 중인 뷰 하나만 다시
만들었다. #867 이후 4분 뒤 패스에는 뷰 캐시 2건이 적중했고, 초기와 재빌드에는 양 시장의 봉 조회 60건 중 30건이
공유 봉 캐시에 적중했다. 한 번 읽는 30종을 최대 6개 병렬로 조회해 원천 활성 시간이 약 1.0초였다. 재빌드의
최근 조회는 10봉 반환 기준이며, 실제 Yahoo 다운로드 범위와 파싱 비용은 이 픽스처로 측정하지 않는다.

모델 개선은 벤치마크 종가를 뷰마다 한 번씩 파싱하고, 오늘 모델과 홀드아웃 모델의 공통 과거 학습 행을 재사용한다.
홀드아웃 모델은 검증 구간 시작 전의 행만 사용한다. 재빌드 뷰 계산은 698ms에서 395ms로 줄었다. 그중 초과수익
시계열 생성은 249ms에서 151ms, 학습 행 생성은 350ms에서 172ms로 줄었다. 200ms 원천 지연에서 30종을 최대
6개씩 조회하면 조회만 최소 약 1초다. 운영의 2초 기준과 화면 요청 대기는 운영 로그 및 별도 화면 벤치에서 확인한다.

### 16시 경계의 느린 패스

2026-11-23 운영 `/api/status`에서 15:58:11 KST는 114ms, 16:00:41은 7.499초였다. 평일 16시는 국장 결과 채점과
국장 일봉을 쓰는 미장 뷰의 준비 시각이다. 이 시각은 캐시 재빌드와 맞물릴 수 있다. 당시에는 원천·모델 소요를
따로 기록하지 않아 두 운영 표본으로 어느 단계가 지연됐는지는 확인할 수 없다. [운영 관측 기록](https://github.com/shindonggeun/trading-desk/issues/864#issuecomment-7093955571)

아래 프로파일은 같은 두 시각에 양 시장을 요청한다. 재빌드에서만 국장 벤치마크 한 종목에 추가 지연 또는
타임아웃·빈 응답을 주입하며, 다른 ETF는 200ms 안에 성공한다. 모든 OHLC와 원천 응답은 합성이다.

```sh
python -m tests.sector_prewarm_profile --runs 1
python -m tests.sector_prewarm_profile --runs 1 --rebuild-origin slow --extra-origin-ms 6900
python -m tests.sector_prewarm_profile --runs 1 --rebuild-origin timeout --extra-origin-ms 3400
python -m tests.sector_prewarm_profile --runs 1 --rebuild-origin empty
```

각 1회 실행 결과다. 15:58:11 패스는 뷰 2건이 적중했고 원천 호출은 0회였다.

| 16:00:41 재빌드 | 전체 전 → 후 | 원천 파이프라인 전 → 후 | 뷰 계산 전 → 후 | 원천 호출 전 → 후 |
| --- | ---: | ---: | ---: | ---: |
| 모두 200ms 성공 | 1.345 → 1.393초 | 1.006 → 1.007초 | 339 → 385ms | 30 → 30 |
| 한 종목이 7.1초 뒤 성공 | 7.924 → 7.456초 | 7.506 → 7.103초 | 418 → 353ms | 30 → 30 |
| 한 종목이 3.6초 뒤 타임아웃 | 7.652 → 4.339초 | 7.203 → 4.005초 | 448 → 333ms | 31 → 30 |
| 한 종목이 빈 응답 | 1.568 → 1.337초 | 1.008 → 1.007초 | 560 → 330ms | 30 → 30 |

타임아웃 전후의 차이는 같은 종목의 두 번째 타임아웃을 생략한 결과다. 성공 응답의 스케줄링 및 뷰 시간은 실행마다
달라진다. 느린 단일 응답만으로도 운영과 비슷한 시간이 나왔으므로, 운영에서 중복 타임아웃이 실제로 발생했다고
판정할 수 없다. 정상 1초와 운영 2초 목표도 이 변경으로 보장되지 않는다.

예외와 빈 응답을 받은 ETF는 마지막 정상 봉을 유지하고 불완전으로 표시한다. 최근 조회가 비었으면 즉시 전체 조회를
추가하지 않는다. 유효한 최근 봉과 기존 봉의 겹침이 달라졌을 때에는 전체를 다시 읽는다. 실패한 원천은 120초 동안
양 시장에서 공유하므로 두 번째 시장이 같은 실패를 기다리지 않는다. 불완전 뷰의 수명과 이후 패스의 재시도는 유지한다.

섹터 재빌드의 INFO 로그에는 시장, 완전 여부, `lock_ms`(다른 섹터 재빌드 대기), `bars_ms`(공유 봉 조회와 원천 처리),
`view_ms`(학습·채점 등을 포함한 뷰 생성), 봉 적중, 최근·전체 호출, `origin_max_ms`, 예외·빈 응답 및 공유 실패 수를
남긴다. 원천 예외는 종류만 기록한다. 뷰 적중은 재빌드 로그를 만들지 않는다. 운영에서는 `/api/status`의 `sectors` 시간과
같은 패스의 재빌드 로그를 대조한다. 시장 둘이 겹쳐 기다릴 수 있어 두 시장의 `lock_ms`를 전체 시간에 더하면 중복된다.

### #905 이후 단계별 검증

2026-11-23 운영의 114ms와 7,499ms는 패스의 섹터 작업 시간만 기록한 표본이다. #884는 합성 재빌드의
모델 비용을 줄였고 #905는 합성 타임아웃의 두 번째 원천 조회를 없앴다. 운영 표본에 단계별 수치가 없어
7,499ms의 원인을 특정할 수 없다. [이슈 관측과 인계](https://github.com/shindonggeun/trading-desk/issues/864)

개발 기준 `1dfd1cd3`에서 앞의 네 시나리오를 각각 3회 실행했다. 종목당 최대 일봉 2,400개, 종목 30개,
원천 호출당 기본 지연 200ms의 합성 환경이다. 초기 패스 12개는 1,544.46~1,737.13ms였고 각 패스가
전체 이력을 30회 읽었다. 안정 구간 12개는 0.12~0.24ms였고 뷰 2개가 적중해 원천 호출이 없었다.
앞의 명령에서 `--runs 3`으로 반복할 수 있다.

| 16:00:41 합성 재빌드 | 전체 중앙값 (최솟값~최댓값, ms) | 봉 처리 / 뷰 계산 중앙값 (ms) | 가장 긴 원천 호출 중앙값 (ms) | 봉 적중 / 실패 재사용 (건) | 2,000ms 이하 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 정상 | 1,573.53 (1,546.40~1,580.96) | 1,010.13 / 564.54 | 201.90 | 30 / 0 | 3/3 |
| 한 종목 늦게 성공 | 7,699.05 (7,691.37~8,061.36) | 7,106.20 / 584.69 | 7,100.15 | 30 / 0 | 0/3 |
| 한 종목 타임아웃 | 4,150.73 (4,144.73~4,554.14) | 3,603.89 / 546.68 | 3,600.35 | 29 / 1 | 0/3 |
| 한 종목 빈 응답 | 1,562.09 (1,541.52~1,570.26) | 1,008.76 / 552.86 | 201.43 | 29 / 1 | 3/3 |

재빌드 12개 모두 최근 봉 30회, 전체 이력 0회였다. 타임아웃과 빈 응답은 각각 패스당 한 번만 주입됐다.
2,000ms 이하인 빈 응답 패스에도 원천 결측이 있으므로 시간과 완전 여부를 함께 본다. 격리 상태 경로 회귀는
초기 전체 읽기, 뷰 적중, 타임아웃과 실패 재사용, 다음 패스 복구를 같은 패스의 상태 응답과 로그로 대조한다.
`pytest -q tests/test_sector_prewarm_observability.py`로 재현할 수 있다.

개발 기준의 `GET /api/status`는 `prewarm.at`, `prewarm.ms`, `prewarm.jobs.sectors`를 반환한다.
`stages`는 합성 프로파일 출력에 있으며, 운영 단계별 근거는 섹터 재빌드 로그에서 대조한다. 운영 확인에는
배포 버전이 일치하는 자연 패스의 서로 다른 `prewarm.at`를 사용한다. 인증된 읽기 전용 경로에서 기록한
`jobs.sectors`의 밀리초를 2,000ms와 비교하고 오류 문자열과 누락은 별도 집계한다. 전체 패스 `prewarm.ms`는
여러 작업의 경과 시간이므로 섹터 기준에 사용하지 않는다. 같은 패스의 양 시장 로그에서 봉 처리, 뷰 계산,
