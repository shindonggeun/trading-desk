# NQ1! 주봉 지지 후보와 NQ=F 검증 (#675)

## 자료와 확인 범위

## 데이터와 시점

- `NQ1!`은 TradingView가 계약을 교체해 이어 붙인 시계열이다. 캡처에는 교체 계약·날짜, B-ADJ 및 결제값 설정이 확인되지 않는다. TradingView는 교체점에서 과거 구간을 조정할 수 있다. Yahoo `NQ=F`의 `auto_adjust=False`는 Yahoo로부터 받은 연속 시계열의 계약별 교체 방법·사후 수정 이력을 보증하지 않는다. 두 소스를 이어 붙이거나 동일 가격을 가정하지 않는다. [TradingView 계약 전환](https://www.tradingview.com/support/solutions/43000689313-switching-continuous-futures/), [TradingView 과거 계약 조정](https://www.tradingview.com/support/solutions/43000685266-how-can-i-enable-backadjustment-for-continuous-futures/)
- 주봉은 뉴욕의 월요일을 주 식별자로 쓴다. 평시 금요일 17:00 ET 이후부터 그 주를 사용한다. 휴일 단축 때에도 이 보수적인 연구 경계까지 기다린다. 개별 휴장·지연·사후 정정으로 원천이 언제 실제로 확정됐는지까지 보장하는 기준은 아니다. [CME Equity Index Futures 거래시간](https://www.cmegroup.com/markets/equities/sp-500-and-nasdaq-100-index-futures.html?redirect=%2Fequityfutures)
- 후속 봉은 신호의 판정과 가격대 계산에 사용하지 않는다. 이미 완성된 신호 봉의 종가로 신호를 판정하고, 반응은 다음 주부터 측정한다. 오늘 받는 역사 데이터로 계산하므로 당시 공급자가 공개했던 원자료를 복원한 시점별 사본은 아니다. 롤 주차별 태그나 개별 계약 시계열을 확보하면 그 주를 분리한 재검증이 필요하다.

## 사전에 고정한 연구 규칙

1. 주봉 워밍업은 직전 55주다. 신호 주를 포함한 최근 52주 최고가에서 신호 주 종가까지 5% 이상 내려온 주를 평가한다. 5% 이상 15% 미만을 일반 조정, 15% 이상을 급락으로 분리한다. 이 조건을 만족한 모든 주가 신호 필터를 걸기 전의 기준선이다.
2. 가격 근거는 직전 확정 주까지만 사용한다. 신호 주 저가와 가격선의 거리가 직전 ATR(14)의 0.5배 이내이면 접촉이다. 저가가 이 범위보다 더 깊게 내려온 주는 종가가 회복됐더라도 이 접촉 표본에 들어가지 않는다. #611 채널은 직전 종가가 채널 안쪽 또는 0.3 ATR 오차 범위에 있는 후보 중 검출기가 먼저 반환한 채널을 쓴다. 피보나치는 k=3 양측 확인을 끝낸 가장 최근 고점 C, 그보다 앞선 저점 B, 다시 앞선 고점 A를 고른다. A와 C는 B보다 높아야 하고, 투영값은 `C × (B/A)^2.618`이다.
3. BB·RSI·채널·2.618을 각각 단독으로 비교한다. 겹침은 접촉한 가격선과 RSI ≤ 30이 함께 나오거나, 동일한 저가에서 두 가격선 이상이 접촉으로 분류된 경우다. 화면 관측값이나 과거 성공률로 입력값을 조정하지 않았다.
4. #240의 시점별 주봉 판정과 사후 관찰을 나누는 방식을 따른다. 두 결과는 다음 주부터 독립적으로 심사하며 한쪽 결과가 다른 쪽의 조건이 되지 않는다.

| 결과 | 확인 조건 | 무효화 |
| --- | --- | --- |
| 단기 반등 | 다음 2주 안에 주봉 종가가 신호 주 고가와 신호 종가 + 직전 1 ATR 중 높은 값을 넘거나 같아진다. | 그 전에 주봉 저가가 신호 주 저가 − 직전 0.25 ATR 밑으로 내려가면 무효다. 같은 봉에서 두 조건을 충족하면 무효를 먼저 기록한다. |

기간은 2016–2019, 2020–2022, 2023–2026으로 고정했다. 두 결과의 표본을 맞추기 위해 각 기간 안에서 이어지는 12개의 완성 주를 모두 확인할 수 있는 날짜만 사용했다. 기간 끝이나 자료 끝에 걸친 후보는 집계에서 빠진다. 신호 실패는 무효화와 기한 내 미확인 건을 더한 값이다. 최대 추가 낙폭은 각 표본의 신호 종가에서 평가 구간 최저가까지의 하락률 중 가장 큰 값이다. 반등이 먼저 확인됐더라도 해당 구간의 전체 저가를 사용한다. 포지션·체결·거래 비용·계좌 누적 낙폭을 평가하는 실험은 아니다.

## 재현

Yahoo의 기존 읽기 경로로 `NQ=F` 주봉 800개를 받아 2026-11-22 05:45 KST 컷오프를 적용했다. 원본에는 2011-08-01부터 2026-11-23 주차까지 연속으로 들어 있었다. 컷오프 이후 2026-11-23 주는 제외되어 799개를 사용했다. 직전 확정 주까지만 따로 저장한 JSON의 SHA-256은 `ee5da88fa9fe189f476530fb233d8e00d6cb714273b844196565085f795a23aa`다. 공급자가 과거 봉을 정정하면 새로 받은 입력 해시와 결과가 달라질 수 있다.

```python
import json
from dataclasses import asdict
from datetime import date, datetime
from pathlib import Path
from zoneinfo import ZoneInfo

from desk.prices import yahoo_candles

new_york = ZoneInfo("America/New_York")
first_week, last_week = date(2011, 8, 1), date(2026, 11, 16)
rows = [
    asdict(bar)
    for bar in yahoo_candles("NQ=F", "1w", 800)
    if first_week <= datetime.fromisoformat(bar.at).astimezone(new_york).date() <= last_week
]
Path("nq-weekly.json").write_bytes(
    (json.dumps(rows, sort_keys=True, separators=(",", ":")) + "\n").encode("utf-8")
)
```

재조회 시에는 2011-08-01 주차까지 가져올 수 있도록 요청 개수를 늘린 뒤 위 날짜 구간으로 자른다. 최초 분석은 2011-08-01에 EMA와 Wilder RSI 계산을 시작했으므로 더 오래된 봉을 함께 넣으면 초기값이 달라질 수 있다. 분석은 다음과 같이 로컬 파일로 실행한다.

```bash
cd backend
python -m desk.nq_weekly_research nq-weekly.json --as-of 2026-11-22T05:45:00+09:00 --output nq-weekly-report.json
```

## 차트 읽기의 주봉 관측 계약

기존 세션 인증 `GET /api/chart-read?ticker=NQ%3DF`의 기본 읽기 또는 `tf`에 `1d`를 포함한 요청은
`weekly_drawdown`을 제공합니다. 여기서는 기존 차트 읽기가 일봉 갭·누적 구간을 위해 가져오는 Yahoo 주봉을 같이
씁니다. 일반 시간봉과 누적·갭 응답은 기존대로 제공됩니다. 다른 종목이나 일봉을 요청하지 않은 호출은 이 필드를
생략합니다. 프론트에서는 차트 자체의 표시 시간봉과 별개로 기본 차트 읽기 요청을 사용합니다.

- `status: "unavailable"`이면 `reasonCode`와 `reason`을 읽습니다. 원천 실패, 지원하지 않는 원천, 주봉 조회 시각
  누락·오류, 주봉 데이터의 공백이나 형식 오류, 최신 주 미수신, 원천의 종결 확인 대기를 구분합니다.
- `status: "available"`의 `week`는 뉴욕 월요일 `start`, 실제 데이터 `source`, `candle: "closed"`, 종결 기준
  `closedAt`, 데이터 조회 시각 `fetchedAt`을 담습니다. `observedAt`은 계산 시각이며 캐시 응답에도 그대로 남습니다.
  조회 완료 시각만으로 마감 직전의 진행 봉을 구별할 수 없어, 일요일 18시 ET 이후 같은 응답에 바로 다음 주 라벨이
  들어온 경우 최신 확정 주를 씁니다. 다음 주 행의 가격은 계산에서 제외합니다. 금요일 마감부터 이 증거가 도착할
  때까지는 `unconfirmed_weekly_close`로 표시합니다. 늦게 시작하는 휴일 주간도 원천의 다음 라벨을 기다립니다.
- `current`의 `price`는 함께 내려오는 차트 봉 중 시작 라벨이 가장 최근인 유효한 봉의 종가 참조값입니다. 라벨이
  같으면 더 짧은 시간봉을 우선합니다. `kind: "chart_bar_close"`, `timeframe`,
  `source`, 봉 시작 라벨 `asOf`, 원천 조회 시각 `fetchedAt`을 돌려줍니다. 체결 시각이나 별도 실시간 호가로
  표시하면 안 됩니다. 참조가 없거나 유효하지 않으면 `price: null`과 결측 이유를 반환합니다.
- `evidence`의 `bollinger`, `rsi`, `channel`, `fib`는 각각 `value`, `state`, `reason`을 담습니다.
  가격 수준은 직전 확정 주까지만 계산하고, 기준 주의 저가·종가로 근접 또는 지지 아래 여부를 읽습니다. RSI는
  기준 주까지의 Wilder RSI입니다. `distancePct`는 유효한 두 가격이 있을 때 `(근거 가격 / 참조 가격 − 1) × 100`이며
  RSI나 가격 결측에는 `null`입니다. `method`와 `anchorWeeks`는 연구에서 사용한 산식과 앵커를 설명합니다.
  원본 캡처 설정·앵커 및 롤오버는 `assumptions.originalSettings`, `originalAnchors`, `rollover`에
  각각 `"unknown"`으로 표시합니다. `assumptions.series`는 `NQ=F`, `referenceSeries`는 `NQ1!`입니다.
- `overlap`의 `state`는 `overlap`, `none`, `missing`입니다. `low/high`는 기준 주에 근접한 연구 가격들의
  범위이며 `basis`는 사용한 근거 키입니다. `usage: "research_only"`는 이 관측의 적용 범위를 뜻합니다.

`rebound`와 `recovery`는 최근 관측 후보 주의 서로 다른 결과입니다. 최근 13개 확정 주 안에서 52주 고점 대비
5% 조정과 연구 가격 근접이 함께 있었던 가장 최근 주를 찾습니다. 후보가 있으면 그 주의 가격·ATR·저항을 고정하고,
후속 확정 주만으로 반등 2주와 회복 12주를 각각 평가합니다. `anchorWeek`는 관측 기준 주, `decisionWeek`는
확인·무효화·만료가 결정된 주, `source`는 판단에 사용한 주봉 원천입니다. `watching`에는 판정 주가 없습니다.
`windowWeeks`, `threshold`, `invalidationLevel`은 각 판정의 관찰 기간과 고정 가격을 제공합니다.
`confirmed`, `invalidated`, `not_confirmed`는 각각 확인, 무효화, 기한 내 미확인이고, 근거가 없으면
`missing`과 결측 이유를 돌려줍니다. 각 판정에 해당하는 `condition` 또는 `invalidation`을 화면에 표시할 수 있습니다.
단기 반등 확인만으로 주봉 추세 회복을 확인하지 않으며 이 필드에는 매매 신호나 승률을 넣지 않습니다.

## 남은 증거

- 캡처의 BB 입력과 STO + RSI 설정, 채널·피보나치 앵커의 날짜·가격, TradingView 롤오버·조정 설정이 필요하다.
- 캡처 후속 12주가 끝나기 전에는 이번 사례의 반등·회복을 이 결과표에 넣을 수 없다. 사용자 제공 알림을 실제 봉과 대조하는 데 필요한 입력과 판정 순서는 아래에 정리했다.

### 외부 알림의 오프라인 대조

`desk.line_alert_replay.compare`에 한 상품의 봉과 알림을 전달한다. 원문 메시지나 계정 정보 대신 아래 메타데이터만 사용한다.

| 입력 | 필요한 값 |
| --- | --- |
| 상품 | 원본 심볼, 만기 또는 연속물 구성·조정·원천까지 식별하는 상품 키, `line_signal` 시간봉 |
| 알림 | 제공 자료 안에서 고유한 메시지 ID, 수신 또는 최초 확인 시각, 정확한 대상 봉 시작 시각, 정규화된 사건 코드, 명시된 목표·무효화 가격 |
| 확정 봉 | 거래소 세션에서 기대하는 봉 순번, 시작·종료·확정 데이터 최초 확인 시각, 저가·고가·종가 |
| 비교 근거 | 우리 선과 기준선 각각 같은 상품·봉·사건에 고정한 목표·무효화 가격과 근거 확인 시각 |

- 모든 시각은 UTC 오프셋을 포함하며 비교 전에 UTC로 변환한다. 스냅샷과 원본의 시간봉이 같아야 한다. `NQ1!`와 `NQ=F`는
  따로 둔다. 알림의 봉 시작·사건 코드가 분명하지 않으면 준비 단계에서 일치 미확인으로 남긴다.
  같은 ID의 상충 기록은 오류로 처리하고, 동일 상품·봉·사건·가격 조합의 재전송은 최초 관측 한 건만 사용한다.
- 우리 선은 알림 관측 시각까지 확인된 확정 봉만 입력해 기존 `line_signals.detect`로 재구성할 수 있다.
  같은 봉·사건의 선이 여럿이면 비교 전에 고른 하나의 선택 규칙을 기록한다. 같은 시점의 무작위 기준선도
  표본을 보기 전에 시드·후보 범위·방향·목표 및 무효화 산식을 고정하고 같은 과거 봉만 사용한다.
  `lines_bt`의 다른 시각에 옮기는 무작위선과는 별도 비교다. 입력 도구는 확인 시각을 검사하며
  전달된 봉·근거의 실제 시점과 가격 수정 이력은 제공 자료에서 증명해야 한다.
- 알림 기준 봉과 관측 시점에 이미 진행 중이던 봉은 결과에서 제외한다. 다음 봉까지 끝난 후 도착한
  알림은 오래된 알림으로 분리한다. 휴장 구간에는 기대 순번을 추가하지 않으며, 순번 누락이나
  결과 시점까지 확정되지 않은 봉에서는 창을 끊는다.
- 세 비교군에 같은 이후 확정 N봉을 적용한다. 고가/저가가 목표 또는 무효화에 닿은 첫 봉을 기록하며,
  한 봉에서 둘 다 닿으면 순서 미확정이다. N봉 전의 자료 부족과 N봉 동안 미도달은 따로 반환한다.
  가격이 명시되지 않은 알림이나 제때 확보되지 않은 근거는 결과를 비워 둔다.

고정 합성 사례는 `pytest tests/test_line_alert_replay.py -q`로 재현한다. 이후 N봉 도달 순서를
검증하는 사례이며 #901의 단기 반등·주봉 회복 기준이나 외부 봇의 규칙은 여기서 추정하지 않는다.
실제 알림 및 당시의 봉·선 스냅샷이 확보되기 전에는 실측 적중률을 집계할 수 없다.
- 주봉 관측 계약의 차트·팁 화면 연결은 #896에서 진행한다.
