# 프로세스 간 최신값과 로컬 캐시 범위 (#689)

공유 대상은 앱의 여러 역할에서 같은 기준으로 읽는 공개 시장 데이터다. 값은 기존 `shared_cache`의 키 결합, 봉인,

각 기존 저장소에 둔다. [공유 캐시 보안 경계](security.md#52-공유-캐시--홈랩-redis-689)

## 기준 develop의 `TTLCache` 분류

기준 `233339be`에는 12개 모듈에 논리 인스턴스 15개가 있다. `live_bars`의 두 생성식은 시계 주입 여부에 따른
같은 인스턴스다. 이미 공유된 3개와 현재 로컬로 유지할 12개를 아래에 정리한다.

| 위치 | 저장 형태와 역할 분류 |
| --- | --- |
| `sr`, `gap_fill`, `oscillator` | 계산 결과를 다른 역할에서도 소비한다. #760에서 이미 로컬 `TTLCache`와 Redis의 2단으로 연결됐다. |
| `estimate._CLOSES` | 공개 마감 봉은 여러 역할이 공유할 수 있는 후보지만, 지금은 날짜·시각을 포함한 로컬 튜플이다. 캔들과 추정가 재사용 설계는 #874 범위다. |
| `estimate._CLOSES_FAILED`, `estimate` 서비스 캐시 | 원천 재시도 제어와 계산 결과·예외를 각각 보관한다. 원천 실패와 예외는 이 프로세스에만 둔다. 추정가 계산 결과는 #874에서 별도 검토한다. |
| `api.movers_cache` | API의 업종 등락 조회 메모다. collector는 장중 지수만 먼저 읽고 급등락 알림 조건을 충족한 경우에만 구성종목까지 읽는다. 평시·휴장 조회를 위한 원천 호출을 추가하지 않고 로컬에 둔다. |
| `filings._subs` | 분석 실행이 소비하는 SEC 8-K·Form 4 제출 목록의 로컬 메모다. 13F 공시의 저장 경로와 별개다. |
| `live_bars` | 프로세스의 실시간 시세 수신과 캔들 결합 결과다. 현재는 로컬 프레임이며 캔들 경로는 #874에서 분리해 다룬다. |
| `longshort` | 성공 결과와 실패 원문 문자열을 같은 캐시에 둔다. 조회 재시도와 실패는 로컬에 두며 공유가 필요하면 공개 결과만 별도 검토한다. |
| `nq_fast._limits` | collector의 원천·시간별 알림 계산에 쓰는 임계값 메모다. 최신 시장 데이터 계약으로 노출할 값이 아니다. |
| `options_detail`의 catalog·chain | 선택적으로 연결되는 원천의 조회와 실패·결측 수명을 제어한다. 현재는 원천별 서비스 메모다. |
| `projection` | 진행 중인 설명 생성과 완료 결과를 같은 프로세스의 작업과 묶는다. |
| `stock_profile._INFO` | 원천의 종목 메타데이터와 원천 예외를 함께 보관하는 조회 메모다. |

## 프로그램 매매 최신값

`GET /api/market/flow`의 일봉 `program` 값은 당일 KRX 프로그램 매매 순매수다. 기존 현물 투자자 수급,
장 전 수급과 장중 시계열은 기존 조회를 사용한다. 프로그램 매매는 collector의 기존 KIS 결과를 선물 스냅샷과 함께
PostgreSQL에 기록하고, 저장 성공 뒤 공개 필드를 시장별·한국 거래일별 Redis 최신값에 게시한다. 프로그램 매매
원천 요청을 추가하지 않는다. 장중 시계열과 정본 DB는 계속 전체 스냅샷을 사용한다.

기존 `at`은 스냅샷 시각이다. `fetched_at`은 collector 확인 시각이고, `source_updated_at`은 KIS가 제공한
한국 거래일의 원천 시각이다. 출처는 `kis`다. 기존 DB 행에는 원천 시각이 별도 기록되지 않아 Redis 값이 없을 때는
`source_updated_at: null`을 명시한다. 원천 시각이 확인 시각을 넘거나 해석할 수 없을 때에도 추정해서 채우지 않는다.
한 시장만 실패했으면 그 시장의 기존 정상값을 보존하고, 다른 시장의 정상 수치는 독립적으로 갱신한다.

API 로컬 적중은 최대 3초 유지하고, 이후 Redis를 읽는다. Redis 값이 없거나 읽을 수 없으면 기존 30초 제어와 당일 DB
조회로 복귀한다. 봉인된 확인 시각으로 쓰기 순서를 비교해 늦게 끝난 과거 스냅샷이 더 최신 확인값을 덮지 못하게 한다.
별도 로컬 메모는 같은 날짜에 이미 본 최신 확인값을 보존해 느린 Redis 응답이나 DB 조회가 값을 되감지 않게 한다.
Redis TTL은 수집 주기보다 30초 길게 잡되 최소 90초, 최대 1시간이다. Redis 실패 시에도 PostgreSQL 기록을 사용한다.

## KOFIA 신용융자·예탁금

`GET /api/market/credit`는 split의 collector가 기존에 읽는 신용융자·투자자예탁금 표에서 공통 통계일의
공개 수치만 공유한다. 두 표를 성공적으로 읽고 합친 뒤 Redis에 봉인해 게시한다. `source_date`는 최신
공통 통계일이고, `refreshed_at`은 두 표를 확인한 UTC 시각이다. 휴장 중 재확인해도 통계일은 그대로다.
같은 키에 여러 관측이 들어오면 통계일을 먼저 비교한다. 같은 통계일에는 전주·전월 변화와 1년 백분위
계산에 사용할 수 있는 자료 범위를 비교한 뒤 확인 시각을 비교한다. 표 하나가 실패하거나 같은 통계일의
짧은 응답으로 계산 근거가 줄어들면 이전 정상값을 유지한다.

API는 받은 전체 통계로 기존 요약과 백분위를 계산하고 `days` 범위만 잘라 반환한다. Redis 값은 최대 7일
유지하며, 같은 프로세스의 동시 Redis 조회를 합친다. Redis가 꺼졌거나 사용할 수 없으면 기존 로컬 값이나
유효 기간 안의 마지막 정상 공유값을 사용한다. 이 지표에는 기존 DB 저장 경로가 없으며, API 요청에서
KOFIA를 새로 호출하지 않는다. collector의 수집 주기와 분석 프롬프트의 로컬 조회는 기존 경로를 사용한다.
